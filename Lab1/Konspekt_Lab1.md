Конспект до лаби 1. Розділ 3, Важливість випадкових чисел (Haunts, с. 25-30)

Для шифрування потрібні випадкові числа, з них роблять ключі. На комп'ютері зазвичай немає апаратного генератора, тому числа генеруються програмно. Через це вони не по-справжньому випадкові, а псевдовипадкові. Щоб вони були хоч трохи випадкові, потрібна ентропія, тобто щось непередбачуване на вході (рух миші, клавіатура, робота диска, мережа). Ентропія це міра невизначеності. На серверах з ентропією гірше, а мережеві події зловмисник може підлаштувати.

Ще в книзі згадується принцип Керкгоффса: безпека має залежати тільки від ключа, а не від того, як усе влаштовано. Тому важливо, щоб ключ не можна було вгадати. Для AES беруть 256 біт (32 байти).

System.Random. Створюється з seed. Однаковий seed дає однакові числа, тобто він детермінований. Підходить для лотереї, кубика чи тестових даних. Можна зробити seed від часу, щоб числа були різні, але для криптографії так все одно не рекомендують. До того ж він не потокобезпечний.

RNGCryptoServiceProvider. Те, що радить Microsoft. Бере ентропію від Windows (ідентифікатор процесу й потоку, час, лічильники, таймери і таке інше). Працює повільніше, але для ключів це не проблема. Метод GetBytes заповнює масив випадковими байтами, для 256 біт треба 32 байти. Для виводу переводимо в Base64.

Висновок: без нормальних випадкових чисел криптографія не працює. System.Random годиться тільки для простих речей, а для ключів треба брати RNGCryptoServiceProvider (у новому .NET це RandomNumberGenerator, його я використав у SecureRnd).
