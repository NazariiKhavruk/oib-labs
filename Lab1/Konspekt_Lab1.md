# Конспект до лабораторної роботи 1: важливість випадкових чисел

Джерело: Haunts S. Applied Cryptography in .NET and Azure Key Vault, розділ 3 (с. 25–30).

Алгоритми шифрування потребують випадкових даних для створення ключів. Апаратного генератора випадкових чисел на комп'ютерах зазвичай немає, тому числа генеруються програмно. Такі числа псевдовипадкові: вони здаються випадковими, але такими не є. Для їх створення потрібне джерело ентропії (випадкових вхідних даних), наприклад рухи миші, клавіатура, активність диска чи мережі. Ентропія є мірою невизначеності. На серверах і мережевих пристроях хороших джерел ентропії мало, а мережеві події зловмисник може підлаштувати під себе.

Стійкість сучасних алгоритмів визначається принципом Керкгоффса: безпека системи має залежати лише від ключа, а не від будови системи. Тобто сила алгоритму дорівнює кількості бітів, які треба вгадати. У книзі використовуються 256-бітні ключі (32 байти) для AES і 2048 та 4096 біт для RSA. Зловмисник не повинен знати жодного біта ключа.

Клас System.Random створюється з початковим значенням (seed). З однаковим seed він завжди видає однакову послідовність. Це підходить для лотереї, кидання кубика або тестових даних, але не для криптографії. Якщо зробити seed залежним від часу, числа стануть різними, але це все одно не рекомендується для криптографії. Крім того, System.Random не є потокобезпечним.

Криптографічно стійкі числа дає RNGCryptoServiceProvider, який Microsoft рекомендує. Він використовує криптографічний провайдер Windows (функція RtlGenRandom, CryptGenRandom). Ентропія береться з ідентифікаторів процесу й потоку, лічильника тактів від запуску, поточного часу, лічильників високої точності, хеша даних користувача (ім'я користувача, ім'я комп'ютера) та внутрішніх таймерів. Він повільніший за System.Random, але для ключів це прийнятна ціна. Метод GetBytes заповнює масив байтів випадковими даними. Щоб отримати 256-бітне число, потрібно запросити 32 байти. Для виведення байти конвертують у Base64.

Висновок: якісні недетерміновані випадкові числа є основою криптографії, без них алгоритми стають вразливими. System.Random придатний лише для простих задач, а для ключів використовують RNGCryptoServiceProvider. У нових версіях .NET його заміною є RandomNumberGenerator, який у лабі використовується в проєкті SecureRnd.
